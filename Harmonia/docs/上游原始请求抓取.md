# DSH 上游原始请求与回复

2026-11-07。全局 DSH Web 的静默启动入口通过 Node `--import` 加载 `scripts/capture-dsh.mjs`，实际记录代码在 `lib/upstream-capture.mjs`。不修改 DSH、pi-ai、SDK 源码、模型配置或代理。该 Web 进程的所有模型供应商调用共用抓取器，包括主脑、审核、主动状态评估、标题等辅助调用及每次实际网络重试；不是只抓 QQbot 的主脑。其他进程启动的 CLI/headless 实例没有自动接入。

## 输出位置

`E:\QQbot\chatlog\YYYY-MM-DD\时间戳-UUID\`。日期和时间戳均为 UTC，`meta.json` 中时间以 `Z` 结尾。

| 文件 | 内容 |
| --- | --- |
| `request.body.raw` | 实际发送的请求体字节；JSON 原始空格、图片 base64、工具定义均保留，可用文本编辑器打开 |
| `request.prepared.raw` | SDK 交给 fetch 的完整序列化请求体；即使 DNS/TLS 失败、未发送任何字节，仍保留完整 JSON |
| `request.headers.raw` | Undici 提交给连接的最终请求行与请求头，包含认证头；HTTP/2 为 Undici 提供的头字段表示 |
| `response.headers.json` | 状态码、状态文字和保持重复字段及顺序的响应头列表 |
| `response.body.raw` | 接收的原始响应体字节，包含完整 SSE；服务端压缩时保留压缩字节 |
| `response.body.txt` | 请求结束后生成的阅读副本；gzip、deflate、br 自动解压，其他情况逐字节复制，保留 SSE 原文 |
| `events.jsonl` | 请求/响应分块的时间、偏移及长度，响应头事件及结束状态 |
| `meta.json` | URL、方法、头字段、连接信息、字节计数、响应 trailers、错误和完成状态 |

根目录的 `capture-status.json` 记录已加载抓取器的 PID、启动时间、Node/Undici 版本以及抓取错误计数。它说明程序已加载，实际有无请求应看日期子目录。不同请求通过同一个目录配对，即使并发、失败或重试也不会混在一起。供应商提供的 request id、SDK 的会话关联头保留在原始头字段里。

抓取期间即可查看 `.raw` 和 `events.jsonl`；阅读副本在收到终态后生成。`completed` 表示 HTTP 响应体完整接收，HTTP 429/500 等仍按原文保存；不表示模型生成成功。`error` 保存传输故障、取消和已收到的部分内容。未发送出去的请求，其 `request.body.raw` 可能为空，完整内容见 `request.prepared.raw`。没有收到响应头时没有 `response.headers.json` 或阅读副本。强制结束进程或断电可能留下 `in-flight` 和部分原文，不能当作完整请求/回复。

## 安装与停用

在工作区运行 `powershell -NoProfile -ExecutionPolicy Bypass -File Harmonia/scripts/install-upstream-capture.ps1`，它只给现有 `%USERPROFILE%\.dsh\Start-Web-Silent.ps1` 添加显式 `--import` 参数，保留代理、静默窗口和其他启动参数。正在运行的进程需在空闲时通过现有服务管理入口重启后加载。不要在执行中的共享 DSH 上直接重启。

停用时，在上述全局启动脚本的 `Start-Process` 参数中移除新增的 `'--import'` 及其紧随的 `capture-dsh.mjs` 路径参数，再在空闲时重启。已有日志保留。若将来替换了全局启动脚本，重新运行安装脚本。

`DSH_CHATLOG_DIR` 仅供独立测试进程把输出隔离到项目根 `.cache` 下；生产默认路径不需要配置。应用测试 `npm test` 覆盖原始字节、并发、压缩、429、取消和连接失败；`npm run test:dsh` 在独立 DSH HOME 和本机假模型上核对最终请求体与服务端实际收到的字节完全一致。

## 边界与保密

- 基于 Undici `diagnostics_channel`，按 DSH 适配器强制携带的 `user-agent: deepseek-harness/...` 选择请求，无模型名称或 API 路径白名单。模型列表等同样携带该标记的供应商调用也会记录。普通网页抓取没有该标记，不记录。
- fetch 入口只旁路保留 SDK 已序列化的字符串/二进制 body，原参数与 Promise 原样传递；不克隆、读取或替换网络流。未来使用 Request 对象或流式上传时，仍记录实际发送字节，但连接建立前失败的上传无法留下完整 prepared 副本。
- 当前安装 Node 24.20.0 / Undici 7.29.0 与 DSH 0.2.1-rc.5 已核对。依赖 Undici 7.11.0 起提供的双向 body chunk 通道；升级后要重跑测试。以后使用不走 Undici 的自定义传输或 WebSocket 模型协议，需要另接其底层抓取点。
- 原始指 HTTP 请求/响应体字节及可观察的头字段；不包含 TLS 密文、TCP 分包、HTTP chunk framing，响应头也不是保留空白格式的网络报文。抓取器不读取供应商内部提示词或供应商未返回的信息。
- **按完整原文保存，认证密钥、私有聊天、记忆、推理字段、图片均可能出现。** 安装脚本将目录访问限制为当前 Windows 用户、SYSTEM 和管理员；`.gitignore` 排除整个输出目录，避免提交。不要公开、转发日志。日志不自动删除，会持续占用磁盘。
- 抓取失败不会取消模型请求或触发重试；会增加 `capture-status.json` 错误计数并输出不含正文/密钥的诊断。磁盘故障时不能保证完整记录，不能把“模型调用成功”等同于“日志完整”。

- DSH `packages/llm/llm-pi-ai/README.md`、`src/adapter.ts`：请求经 pi-ai 转为供应商协议，本机安装的 `lib/index.js` 已逐段核对。
