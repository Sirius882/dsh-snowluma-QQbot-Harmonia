# dsh-alive 智能状态控制

2026-11-07，依据根目录《待办.md》实施。取代旧的聊天关键词判定和固定主动评分，不增加独立的主动开口调度器。沿用dsh-alive只绑定主人私聊的范围：QQ和微信共同计数和更新同一份状态，普通群聊及访客不参与。

同日按主人要求关闭亲密模式，并撤销LUST_EXTRA条件模型路由及转接开关。普通／主动聊天沿用DSH全局默认Astra low；其他情绪、状态评估、主动机制及历史保持。DSH中已配置的DeepSeek模型保留供其他用途，不由Harmonia自动转接。

## 聊天、计数和倒计时

- 桥接完成筛选和审核，决定回复主人私聊后，记录一条输入，再开始推理。重复消息、被拒消息、群聊不计数。
- QQ／微信每条文字泡、图片／表情、文件及qq_share卡片获得平台成功回执后，才记录一条输出。模型生成成功不算发送成功，部分发送只记已确认部分；不确定发送沿用原有不自动重发规则。戳一戳是通知，不算聊天消息。
- 每条输入／确认输出刷新4分钟倒计时。失败通知也算实际发言，但保留“对方还在等正式回复”的事实。
- 主人私聊每轮正常JSON都明确包含`aliveUpdate`对象；累计收发不足6条且计划输出不会跨线时用`{}`，达到6条时完成状态评估，只包含需要改变的状态，无变化仍用`{}`。输入已达6条可在轮次结束时应用，否则等实际输出回执达到6条后应用；不足一组的余数继续计数，不为此另起请求。漏字段、格式错误或校验拒绝均保留到期计数，并在下一轮明确要求补评，不伪装成功、不丢弃正常聊天、不退回关键词判定。4分钟沉默评估仍按下面的规则独立清零。
- 4分钟到点立即清零计数，只进行一次内部评估。“聊5条、等5分钟、聊5条、沉默”只在两次停顿后各评估一次。评估不会触发主动发送，也不会自动续订自身。

内部评估通过DSH的`llm.stream`直接执行，绕过agent聊天轮次、工具执行器、聊天历史追加、长期记忆写入和主动outbox。即便模型误输出聊天内容也不会投递给QQ／微信。保留工具声明仅为复用原请求前缀，模型提出的工具调用不会执行。

提示明确区分主人等达妮娅回复、话题自然结束、已确认主动找主人但尚未获回复。没有已读证据就不推断已读；操作性限制、换话题、引用或玩笑不自动等同关系拒绝。

## 请求前缀与缓存

通过DSH官方`llm/stream`中间件，在实际聊天请求发出前保存模型选择、消息序列、工具声明及工具历史；忽略会话命名／压缩等带`purpose`的辅助请求。

倒计时评估复用最后一条真实聊天模型请求的完整前缀，只在尾部追加内部评估说明和最新事实；原时钟原样保留，新的北京时间写在尾部，不重建前文。沿用该聊天请求实际使用的主模型，不切换全局默认模型。这样具备前缀缓存复用条件，但缓存驻留、提供商路由和计费由提供商控制，不保证“4分钟以内全部命中”。

请求保存在私有运行文件`runtime/alive/alive-last-request.json`；计数、截止时间、去重及评估状态保存在现有`alive-state.json`的`chatAI`中。不依赖`.cache`保存长期状态。重启可恢复待处理倒计时，超过四天的旧请求不会重放。确认收发的派生记录复用四天／50条批量裁剪，评估尾部只补最多6条简短收发事实。

## 兼容的状态变更契约

所有字段均可省略。模型不能写配置总开关、hardOff、真实配额计数、目标会话、接收人或发送状态。

| 输出字段 | 接受的变化 |
|---|---|
| `moodUnit`、`mood` | 修改mood必须同时带`moodUnit:"percent"`。输入和输出的missing、jealousy、warmth、worry、boredom、annoyanceDebt、lust统一为0–100百分比；恼火由程序转换为原0–60欠账，其余转换为内部0–1。示例57%写57，0.57%才写0.57，不猜测小数应放大100倍。可选mood.lustPhase为grow／decay；亲密模式关闭时不改变lust及阶段 |
| `control` | mute／unmute；mute沿用minutes、hard及user-said-stop／user-busy／people-around三类原因，接受软／硬静音仍遵循设置 |
| `loops` | 按已有id把相关事件标成answered／abandoned／stale，不改尝试次数；free／greeting没有平台确认sentAt时，禁止标answered，普通约定事项仍可按语境关闭 |
| `intent` | 最多一个新事项，沿用food／sleep／departure／promise／task_handoff／interrupted六类及what、quote、backInMin、confidence、moodHint字段 |
| `episode` | 对已有且有实际发送证据的主动记录判定replied／ignored，据此更新原回应统计，不伪造送达 |
| `goodbyeUntil` | 道别暂缓主动的截止时间或null，取代旧道别正则；到期比较由程序处理 |

解析接受JSON代码块或带前后说明的JSON对象。缺少情绪单位、未知字段、越界值、未知事件类型及非法状态会拒绝该批格式错误的更新。通过格式校验后，关闭未送达事项等非法操作仍由宿主逐项拦截；存在拒绝时不将整次评估记为完成。无法解析、请求失败或超时时保留原状态并记录无正文错误状态；不自动重跑完整聊天，不退回旧识别器。新输入、管理员手动改情绪或reset会使正在评估的旧结果失效。reset清除这部分派生记录和请求快照，保留原情绪、配额及长期记忆。

## 主动投递和诊断

主动来源与loopId按turn/start到turn/end的真实轮次保存，只由proactive消息建立；后续runtime-context、状态评估、skill-catalog和dsh-alive等辅助注入不会覆盖。完成轮次最多生成一份候选；普通轮次、失败轮次和重复结束事件不生成。模型生成或提交DSH均不充当平台发送证据，仍由原投递器确认sentAt。

`.cache/harmonia/alive-logs/assessment.jsonl`记录内联／沉默／Terra评估触发、百分比前后值、控制与事项状态变化、拒绝原因、漏交待评估计数，以及主动候选是否成功入队。仅写内部关联ID、数值和固定状态，不写聊天正文、原始模型输出或凭证；达到2MiB轮转并保留一份旧日志。清空.cache只清除诊断资料，不影响runtime中的计数、情绪、配额和去重。

## 连续对话中的傲娇倾向

这是表达方式的连续倾向，不加入原七项情绪，不参与原主导情绪／亲密模式判定。仅作用于主人QQ／微信共享私聊。唯一人设仍是每轮动态读取的PERSONA.md；低值也不代表减少爱意或真的拒绝陪伴，不能用它覆盖主人真实的停止要求。

- 0为极傲、100为极娇；从冻结状态开启新对话时为25。发出／收到每条实际消息刷新30分钟截止时间，分泡、媒体、文件按原确认回执计数，不按标点拆句。30分钟无收发后重置25并冻结，新的对话再次启动。旧运行状态首次加载此功能时初始化为冻结，不追溯旧发言触发追话。
- 对话主模型每轮额外给出`tsundereUpdate:{k,delta,received:[{id,delta}],sent:[delta,...]}`。提示词要求每次傲娇评估同时显式返回有限数值`k`和`delta`：前者决定后续时间变化，顶层`delta`立即修正当前值，无即时修正也要求返回0。程序逐项接纳：只返回合法k就只更新系数，只返回合法delta就只修正当前值；另一项缺失或非法不连带拒绝合法项，也不将缺失k默认为0。尚未得到首次合法k时保持null，不假定时间变化方向。收到的消息由ID关联，发出的增减按bubbles／sticker／images／files顺序等待真实成功回执逐条应用；这些逐消息增减不重复计入顶层`delta`，生成成功而发送失败不应用对应输出增减。逐消息计划不完整或非法时，不影响独立合法的k／delta，仍核对消息ID及回执，避免错配。输入含义由同一轮模型判断并据此组织回复，不另起每消息的评估请求；傲娇不受6条情绪评估门槛限制。激活期间的沉默评估同样要求返回`tsundereUpdate:{k,delta}`并逐项使用。新输入或手动调整会使旧轮次结果失效。整项缺失或完全没有可用变更时保留已有参数、记录内存中的`tsundere.lastError`，不会丢弃正常聊天。
- `k∈[-1,0)∪(0,1]`，由主模型依据消息、上下文和当前情绪决定。有限数超界截到±1，0、非数值和无穷值拒绝；尚未得到首次合法k时不假定默认语义方向。思念较高通常更快转娇、较难回落，吃醋／恼火通常较慢增长、较易回落，这些关系由模型结合语境判断，不再叠加固定关键词或权重。

以分钟为时间单位，固定函数为：

```text
dx/dt = k · f(x),   f(x) = (x + 20) / 3
x(t) = (x₀ + 20) · exp(k·t/3) - 20
```

程序在对话激活期间每秒精确积分并更新内存，不执行秒级保存；实际收发也按经过时间立即推进。冻结后停止每秒定时，不增加模型请求，也不加快原插件其他情绪或主动调度的心跳。时间尺度已从30分钟改为3分钟，速度为初版的10倍。正向自然变化到60封顶，已经通过消息达到60以上时保持原值，不能被封顶反压回60；负向变化最低为0，消息导致的直接增减仍允许达到100。相同正k下，当前越娇，单位时间增长越快。例：从25、k=0.5开始，3分钟后约54.19；k=1时约104秒到达60；k=-0.5时3分钟后约7.29。30分钟无收发仍到截止直接重置冻结，3分钟“急了”仍使用最后发出时的快照，均不因每秒刷新而延后。

### “急了”：修复口是心非造成的误会

最后一条确认发出的消息，若**发出当时**的倾向严格低于24，启动3分钟计时；24本身不触发，初始25也不触发。之后每个回复泡都会更新“最后一条”的时刻和值；收到主人消息则取消旧计时。失败通知不启动追话。到点仍没收到主人消息时：

1. 先把傲娇与担心分别至少拉到80，超过80的值保留；在内存中标记本次已触发，超时／失败不自动重投。重启后丢弃整段临时状态及计时，不重放旧追话。
2. 复用DSH原生`agent.followup`和现有主动outbox，附带最近真实确认聊天、当前状态与北京时间，让达妮娅承接上一句话解释真实心意、软下来拉回话题。它不是新开话题，无需新检索或Terra主动评分，不断言对方已读或真实想法。
3. 按主人明确选择，不占新话题的小时／滚动24小时配额，不改配额时间，不受45分钟沉默、2小时冷却或恼火阈值压制；继续复用dsh-alive硬闸，保留总开关、hardOff、真实静音／停止、夜间静默和会话忙碌检查。被硬闸阻止时本次不延后补发。
4. 后续机器人发言不重新解锁；只有主人新的输入才能重新允许下一次“急了”。主人在生成或排队期间回来，旧续接标记即失效；outbox投递前向运行中的插件查询内存标记、30分钟有效期与硬闸，沿用不确定发送不重试。重启从冻结25开始，旧候选没有匹配的内存标记，会被取消；插件查询失败同样不投递。

傲娇状态只存在DSH插件进程的内存中，不序列化到`alive-state.json`，普通保存也排除该对象；启动时忽略旧文件中的傲娇字段，并随正常状态保存移除旧字段。自然变化不写盘，数值与k不再追加专用状态日志；诊断只保留评估成功／拒绝和“急了”触发／阻止等事件。既有上游请求抓取与完整请求快照维持原规则，可能含当时注入的历史数值，但不作为傲娇恢复源。`/reset`同时冻结这段临时状态、作废尚未送出的旧续接，不清原情绪、配额或长期记忆。

同一认证端点`/harmonia/alive-chat`的POST仍接收真实收发；GET以相同Bearer令牌只读查询当前内存状态与续接硬闸结果，并设置no-store，不刷新聊天计时。桥接仅在有续接候选时查询，不每秒跨进程轮询。

## 时间推进与Terra

- 原`mood.evolve`自然增长／回落公式、心跳和GUI数值设置继续使用。
- 明确的开关、时间到期、时段问候、情绪阈值、次数、静默、冷却和配额仍由程序计算。
- 技术硬闸通过后的主动软评分使用当前提供商下的`gpt-6.1-terra`、low，无工具、一次性调用；输出原0–100评分，仍与设置的threshold比较。固定权重评分函数已删除。
- 事件按期限作废仍由程序完成，“未回应意味着什么、如何影响情绪”交给Terra，提供是否有实际发送回执的事实。
- 同一候选、相同聊天版本的评分最多复用10分钟，失败也短暂记住，避免每跳反复请求；新聊天或手动情绪调整使旧评分失效。问候仍按时钟与设置执行，不调用评分模型。
- 不改变全局模型选择，不修改dsh-alive配额算法、followup等待方案或桥接发送去重。

## 实现和验证入口

- `plugins/dsh-agent/alive-intelligence.mjs`：倒计时、计数、请求快照、内部评估及Terra。
- `lib/alive-assessment.mjs`：提示契约、容错解析、字段验证与状态应用。
- `lib/alive-emotion.mjs`、`lib/alive-audit.mjs`：共享情绪单位换算、无正文状态变更日志。
- `lib/tsundere.mjs`：傲娇积分、连续对话生命周期、模型变更契约与续接硬闸。
- `lib/alive-chat.mjs`及两端适配器：认证本地收发事件和实际成功回执。
- `scripts/patch-alive.mjs`：安装时复用的幂等补丁，删除被替代的关键词、道别、固定评分及聊天事件数值回调，保留时间演化与投递规则。

`npm test`验证应用；`node scripts/verify-dsh.mjs --alive`在隔离DSH与本机假模型上额外验证六条消息、实际agent.followup主动来源及outbox、真实3分钟“急了”和4分钟沉默定时器，需要约7分钟等待，不会向真实联系人发送测试消息。`--alive-inline`省略两项真实等待。
