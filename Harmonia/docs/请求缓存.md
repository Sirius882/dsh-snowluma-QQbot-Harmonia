## 现行请求结构

2026-11-07增加[智能状态评估](dsh-alive智能状态控制.md)：主人私聊普通请求在末尾补内部状态要求；4分钟倒计时评估复用最后真实模型请求的完整前缀，只追加状态评估尾部和新时钟。实际缓存命中仍取决于提供商，不保证驻留时间或命中比例。

系统提示先放人设、权限、输出格式等固定规则，末尾仅附一份明确标为无指令权限的JSON长期记忆快照。每轮热读唯一PERSONA.md及权威memories.json；记忆变更通过快照与尾部增量立即生效；时间不放系统提示，不冻结时间或权威记忆来换命中。

普通请求的资料按变化频率排列：系统固定规则及引用记忆、可信身份、逐条近期聊天、本轮表情候选与含义、当前消息及图片、记忆增量，最后附北京时间。DSH模型请求把路由元数据、逐条历史、本轮消息拆成独立user消息，不重复注入记忆；历史里的角色仍只是资料，不提升为系统或开发者指令。原始入站路由封装及日志保留，dsh-alive仍只识别本轮真实主人文本。DSH的时钟是本轮输入的最后一个内容块；Codex回退的时钟是最终JSON字段。DSH必须提供的工作目录等运行上下文仍由宿主管理。

主动消息同样在系统末尾使用统一记忆快照，再附近期聊天、表情候选和主动任务，尾部附记忆增量与时间。dsh-alive解析可信主人消息时单独读取路由JSON块，避免尾部时钟破坏消息识别。

当前提供商虽然兼容Responses，但实测拒绝显式缓存参数（400：prompt_cache_options is not supported on this model）。因此不发送prompt_cache_breakpoint/prompt_cache_options，不修改共享DSH适配器、缓存模式或TTL，只使用兼容的请求顺序与消息拆分。不能把OpenAI官方接口支持的参数直接当作当前提供商也支持。

实际DSH工具定义及顺序在相邻轮次保持一致。历史改为四天/50条批量窗口：达到50条丢最早30条，最早记录满四天丢最早三天。批次内追加，达到边界集中重建；不填回已移除记录，不保留过期内容来换命中。


## 稳定快照和增量

唯一权威仍是memory/memories.json，bot自由维护该文件。runtime/memory-prompt.json仅保存派生snapshot和按发生顺序追加的delta，不构成第二份独立记忆。按条目id比较规范化内容，JSON缩进、字段顺序、数组重排不造成快照变化。

新增和状态/来源元数据变化追加尾部增量，系统快照不变；累计20条增量或增量JSON达到8KiB时合并。任何已有条目的原文修正、删除或遗忘立即合并，保证旧原文不进入下一轮。权威文档已先更新，快照丢失或损坏时由其重新生成；不把派生状态放.cache。

DSH系统组装与首步中间件按同一轮AbortSignal绑定同一份快照/增量，避免并发轮次把不同版本配在一起。该配对在本轮内固定，文件工具的当前修改仍由工具结果告知模型，下一轮重新读取权威状态。增量插在当前时间之前，后写条目覆盖同collection、同id的快照资料；引用及增量均没有指令权限。Codex回退使用相同快照与增量规则。

验证入口：`npm test`覆盖资料顺序、时钟位置、图片顺序、主动轮次和主人文本解析；`npm run test:dsh`比较本机假模型实际收到的相邻请求，断言系统提示及工具定义一致、历史增长及表情变化保留长期记忆前缀。字符比较报告在根`.cache/harmonia/cache-prefix-check.json`，它不代表提供商实际命中的token数。真实提供商指标需以其usage回报为准；不记录真实聊天正文或密钥作为缓存诊断日志。
